# Analýza a architektura: Šťastný statek – LibreOffice Base

## 1. Je LibreOffice Base vhodný nástroj?

### Závěr: **ANO – s vědomím hranic**

LibreOffice Base 26.2 s vestavěným Firebird 3 je pro Šťastný statek **dostatečný a vhodný nástroj**, pokud:
- jde o **jednouživatelský provoz** (jedno PC, případně záloha na cloud),
- je design databáze pečlivě navržen **dopředu** (ALTER COLUMN nefunguje),
- jsou pro automatizaci využita **makra LibreOffice Basic**,
- generované dokumenty jsou uloženy jako soubory na disku (ne v DB jako BLOB).

### Co LO Base zvládne bez problémů

| Funkce | Hodnocení | Poznámka |
|--------|-----------|----------|
| Evidence zákazníků, dětí, rodičů | ✅ | Tabulky + formuláře s podformulářem |
| Evidence praktikantů | ✅ | Samostatná tabulka |
| Přihlášky na dětské akce | ✅ | Tiskový formulář nebo sestava |
| Zálohové a doplatkové faktury | ✅ | Tiskový formulář + makro pro číslování |
| Evidence termínů / turnusů | ✅ | Tabulka Akce/Turnusy |
| Vazby rodič ↔ dítě | ✅ | FK + podformulář |
| Správa cest k dokumentům | ✅ | VARCHAR pole, otevírání souboru makrem |
| Sestavy (seznamy dětí, Kooperativa) | ✅ | Report Builder nebo dotazy |
| Evidence příjmů | ✅ | Tabulka Faktury + dotazy |
| Formuláře bezinfekčnosti | ✅ | Přes evidenci dokumentů |
| Automatické číslování faktur | ✅ | Makro + sekvence Firebird |
| Export / tisk do PDF | ✅ | Nativně v LO |
| Hromadné informace rodičům | ⚠️ | LO nepodporuje přímý e-mail; export seznamu adres do Writeru (hromadná korespondence) |
| Víceuživatelský přístup | ❌ | Embedded Firebird = 1 uživatel |

### Klíčová omezení Firebird embedded v LO Base

> [!WARNING]
> Tato omezení **musí být respektována při návrhu**. Nelze je obejít až zpětně.

1. **Žádný `AUTO_INCREMENT`** – ID se generují pomocí `GENERATED BY DEFAULT AS IDENTITY` (LO Base 26.x / Firebird 3) nebo pomocí `SEQUENCE` + `TRIGGER`
2. **`ALTER COLUMN` nefunguje** – typ sloupce nelze změnit po vytvoření; nutné plánovat dopředu
3. **SQL příkazy se vkládají jeden po druhém** – `Nástroje → SQL` nezpracuje dávku více `CREATE TABLE` najednou
4. **Žádné uložené procedury** – logika se řeší makry LibreOffice Basic
5. **BLOB soubory v DB jsou nevhodné** – ukládají se pouze cesty k souborům
6. **Délka názvů tabulek a sloupců** – max. ~31 znaků; bez diakritiky v názvech objektů DB

## 2. Je XRechnung_V2602_010.odb vhodný jako základ?

### Závěr: **Částečně – jen fakturační část**

Databáze XRechnung implementuje **německý standard elektronické faktury EN 16931**, který je výrazně složitější, než potřeby Šťastného statku.

| Část XRechnung | Použitelnost |
|---------------|-------------|
| Tabulky pro faktury (`Rechnungen`, `Rechnungspositionen`) | ✅ Inspirace pro strukturu |
| Tabulky zákazníků (`Kunden`, `Kontaktpersonen`, `Adressen`) | ✅ Inspirace |
| Platby (`Zahlungen`, `Zahlungsbedingungen`) | ✅ Inspirace |
| Dokumenty (`Dokumente`, `Anhaenge`) | ✅ Inspirace |
| Sestavy (4 sestavy – faktura A4, seznam zákazníků) | ✅ Inspirace pro layout |
| XRechnung-specifické tabulky (EASCode, Steuerkategorie, MIME, EU normy) | ❌ Nevhodné, zbytečná komplexita |
| Německé názvy polí a logika | ⚠️ Nutný překlad/přepis |

> [!IMPORTANT]
> **Doporučení:** XRechnung **nepoužívat jako základ** pro kopírování. Místo toho postavit **novou čistou databázi** `Šťastný_statek.odb`, přičemž XRechnung slouží jako **referenční inspirace** pro strukturu faktur a tiskové sestavy.

#### T1: `Dodavatele` (Vaše firma – údaje pro faktury)

CREATE TABLE "Dodavatele" (

  "Web"           VARCHAR(100),

  "Cislo_Uctu"    VARCHAR(50),
  "IBAN"          VARCHAR(50),
  "Logo_Cesta"    VARCHAR(500)

---

#### T2: `Akce` (všechny typy akcí + jejich termíny/turnusy)
```sql
CREATE TABLE "Akce" (
  "ID_Akce"         INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  "Typ_Akce"        VARCHAR(30) NOT NULL,
    -- VYJIZDKA | BALICEK_1D | BALICEK_2D | DETSKY_VIKEND | LETNI_TABOR | PODZIMNI_PRAZDNINY
  "Nazev"           VARCHAR(100) NOT NULL,
  "Datum_Od"        DATE,
  "Datum_Do"        DATE,
  "Kapacita"        SMALLINT,
  "Cena_Celkem"     DECIMAL(10,2),
  "Zalohova_Castka" DECIMAL(10,2),
  "Zalohova_Spl"    DATE,         -- výchozí datum splatnosti zálohy
  "Poznamka"        VARCHAR(500),
  "Aktivni"         SMALLINT DEFAULT 1  -- 1=aktivní, 0=archiv
);
```

> Vyjížďky a balíčky nemají přihlášku, ale mají datum (= Datum_Od). Dětské akce mají Datum_Od i Datum_Do (turnus).

---

#### T3: `Praktikanti` (2–3 praktikanti přihlášení k dětské akci)
```sql
CREATE TABLE "Praktikanti" (
  "ID_Praktikanta"   INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  "Jmeno"            VARCHAR(50) NOT NULL,
  "Prijmeni"         VARCHAR(50) NOT NULL,
  "Datum_Narozeni"   DATE,
  "Telefon"          VARCHAR(20),
  "Email"            VARCHAR(100),
  "Adresa"           VARCHAR(200),
  "Poznamka"         VARCHAR(500)
);
```

#### T3b: `Praktikanti_Akce` (vazební tabulka M:N)
```sql
CREATE TABLE "Praktikanti_Akce" (
  "ID"              INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  "ID_Praktikanta"  INTEGER NOT NULL,
  "ID_Akce"         INTEGER NOT NULL,
  CONSTRAINT "FK_PrakAkce_Prakt" FOREIGN KEY ("ID_Praktikanta")
    REFERENCES "Praktikanti"("ID_Praktikanta") ON DELETE CASCADE,
  CONSTRAINT "FK_PrakAkce_Akce"  FOREIGN KEY ("ID_Akce")
    REFERENCES "Akce"("ID_Akce") ON DELETE CASCADE
);
```

---

#### T4: `Zakaznici` (rodiče, dospělí na vyjížďky, platitelé)
```sql
CREATE TABLE "Zakaznici" (
  "ID_Zakaznika"   INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  "Jmeno"          VARCHAR(50) NOT NULL,
  "Prijmeni"       VARCHAR(50) NOT NULL,
  "Telefon"        VARCHAR(20),
  "Email"          VARCHAR(100),
  "Ulice_CP"       VARCHAR(100),
  "Mesto"          VARCHAR(50),
  "PSC"            VARCHAR(10),
  "ICO"            VARCHAR(20),
  "DIC"            VARCHAR(20),
  "Poznamka"       VARCHAR(500)
);
```

---

#### T5: `Deti` (děti na dětské akce, vázané na zákazníka/rodiče)
```sql
CREATE TABLE "Deti" (
  "ID_Ditete"          INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  "ID_Rodic"           INTEGER NOT NULL,   -- FK → Zakaznici (platící rodič/zákonný zástupce)
  "Jmeno"              VARCHAR(50) NOT NULL,
  "Prijmeni"           VARCHAR(50) NOT NULL,
  "Datum_Narozeni"     DATE NOT NULL,
  "Zdravotni_Pojistovna" VARCHAR(100),
  "Cislo_Pojistky"     VARCHAR(30),
  "Urazove_Pojisteni"  SMALLINT DEFAULT 0, -- 0=nemá, 1=má (pro seznam Kooperativa)
  "Zdravotni_Omezeni"  VARCHAR(500),
  "Bezinfekcnost"      SMALLINT DEFAULT 0, -- 0=neodevzdáno, 1=odevzdáno
  "Datum_Bezinf"       DATE,
  "Poznamka"           VARCHAR(500),
  CONSTRAINT "FK_Deti_Rodic" FOREIGN KEY ("ID_Rodic")
    REFERENCES "Zakaznici"("ID_Zakaznika") ON DELETE CASCADE
);
```

---

#### T6: `Dokumenty` (cesty k souborům – pro děti i praktikanty)
```sql
CREATE TABLE "Dokumenty" (
  "ID_Dokumentu"    INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  "Typ_Osoby"       VARCHAR(10) NOT NULL,  -- DITE | PRAKTIKANT | ZAKAZNIK
  "ID_Osoby"        INTEGER NOT NULL,       -- FK podle Typ_Osoby
  "ID_Prihlasky"    INTEGER,                -- volitelně vázán na přihlášku
  "Typ_Dokumentu"   VARCHAR(50) NOT NULL,
    -- PRIHLASKA | FAKTURA | LEKAR | BEZINFEKCNOST | POJISTOVNA | ZDRAVOT_OMEZENI | JINE
  "Nazev"           VARCHAR(200),
  "Cesta_Souboru"   VARCHAR(500) NOT NULL,
  "Datum_Vlozeni"   DATE,
  "Poznamka"        VARCHAR(300)
);
```

---

#### T7: `Prihlasky` (registrace zákazníka/dítěte na akci)
```sql
CREATE TABLE "Prihlasky" (
  "ID_Prihlasky"     INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  "ID_Akce"          INTEGER NOT NULL,
  "ID_Zakaznika"     INTEGER NOT NULL,   -- platitel / rodič
  "ID_Ditete"        INTEGER,            -- NULL pro vyjížďky a balíčky
  "Datum_Prihlasky"  DATE NOT NULL,
  "Stav"             VARCHAR(20) DEFAULT 'PRIHLASEN',
    -- PRIHLASEN | POTVRZEN | STORNO
  "Variabilni_Symbol" VARCHAR(20),
  "Cena_Celkem"      DECIMAL(10,2),
  "Poznamka"         VARCHAR(500),
  CONSTRAINT "FK_Prih_Akce"  FOREIGN KEY ("ID_Akce")
    REFERENCES "Akce"("ID_Akce") ON DELETE CASCADE,
  CONSTRAINT "FK_Prih_Zak"   FOREIGN KEY ("ID_Zakaznika")
    REFERENCES "Zakaznici"("ID_Zakaznika") ON DELETE CASCADE,
  CONSTRAINT "FK_Prih_Dite"  FOREIGN KEY ("ID_Ditete")
    REFERENCES "Deti"("ID_Ditete") ON DELETE SET NULL
);
```

---

#### T8: `Faktury` (zálohové a doplatkové faktury)
```sql
CREATE TABLE "Faktury" (
  "ID_Faktury"       INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  "ID_Prihlasky"     INTEGER NOT NULL,
  "Typ_Faktury"      VARCHAR(15) NOT NULL,  -- ZALOHOVA | DOPLATKOVA
  "Cislo_Faktury"    VARCHAR(30) NOT NULL,  -- generováno makrem
  "Castka"           DECIMAL(10,2) NOT NULL,
  "Castka_Zaplaceno" DECIMAL(10,2) DEFAULT 0,
  "Datum_Vystaveni"  DATE NOT NULL,
  "Datum_Splatnosti" DATE NOT NULL,
  "Datum_Zaplaceno"  DATE,
  "Uhrazeno"         SMALLINT DEFAULT 0,    -- 0=ne, 1=ano
  "Variabilni_Symbol" VARCHAR(20),
  "Poznamka"         VARCHAR(500),
  CONSTRAINT "FK_Fakt_Prih" FOREIGN KEY ("ID_Prihlasky")
    REFERENCES "Prihlasky"("ID_Prihlasky") ON DELETE CASCADE
);
```

## 13. Otevřené otázky pro odsouhlasení

> [!IMPORTANT]
> **Otázka 1 – Vztah rodič ↔ dítě:**
> Může mít dítě **dva rodiče** (oba kontakty) v jednom záznamu, nebo stačí jeden zákonný zástupce (platitel)?
> - Varianta A (jednoduchá): Dítě má právě jednoho rodiče (ID_Rodic)
> - Varianta B (komplexní): Vazební tabulka `Rodice_Deti` s oběma rodiči
> Starší prototyp `schema.sql` používal Variantu A – navrhujeme ji zachovat a u druhého rodiče použít pole `Poznamka` nebo rozšířit Zákazníky o `Jmeno2_Rodice` + `Telefon2`.

> [!IMPORTANT]
> **Otázka 2 – Vyjížďky a balíčky bez přihlášky:**
> U vyjížděk a balíčků u koní nevzniká přihláška – jen faktura. Navrhujeme:
> - Vytvořit přihlášku i pro tyto akce (systémově jednotné), ale **netisknout ji**
> - Nebo přidat do Faktur přímý odkaz na Zákazníka bez přihlášky (dvě oddělené logiky)
> **Doporučujeme Variantu 1** (vždy přihláška) pro jednoduchost databázového modelu.

> [!IMPORTANT]
> **Otázka 3 – Číslování faktur:**
